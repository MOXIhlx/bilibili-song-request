## 1. 图库缩略图下方的「大图展示」比例不对

| 项 | 内容 |
|---|---|
| 状态 | **待修（已选定方案）** |

## 2. 图库缩略图把图片「平铺开」

| 项 | 内容 |
|---|---|
| 状态 | **已定位（原因明确）** |
| 现象 | 中间那张缩略图把整张图**平铺**重复显示（截图 1 第二格） |
| 定位结果 | `.bg-thumb` 用 **`background` 简写**声明了**两层**背景：<br>`background-size: 16px 16px, cover;`<br>`background-repeat: repeat, no-repeat;`<br>而模板用的是**行内样式只覆盖一层**：<br>`:style="{ backgroundImage: url(...) }"`<br>行内只给了一层 `background-image`，CSS 里那两层的 `repeat` / `size` 就对不上号——第二层的 `cover` / `no-repeat` 落空，图片按默认 `repeat` 平铺 |
| 修法（待实施） | 行内样式补齐两层，或把棋盘格换成 `::before` 伪元素，让 `background-*` 只服务图片一层 |
| 影响面 | 只影响设置页展示 |
| 改动位置 | `ObsPanel.vue` 模板 L1655 与 `.bg-thumb` 样式 |
| 备注 | 与第 1 条同源：都是「简写属性 + 行内覆盖」的层数不匹配 |

## 4. 左右旋转 90° 角度不对，连点四下无法回正

| 项 | 内容 |
|---|---|
| 状态 | **已定位** |
| 现象 | 旋转角度不对；连点 4 次（应回到 0°）回不正 |
| 定位结果 | ① 模板传的是 `rotate(±90)`，而 `$rotate()` 内部是**相对当前角度**再转，理论上 4 次该回正 → 所以问题多半出在"每次旋转后 canvas 尺寸/选区没重算"；<br>② 更可疑的是 `rotatable` 属性写法：原生 HTML 里 `rotatable` 作为 attribute 出现即视为 true，但 cropperjs 读的是**属性值**。若它拿到的是空字符串而非 `true`，旋转会被内部判断直接跳过——表现就是"点了没反应或角度不对" |
| 待验证 | 点击后读 `imageEl.rotation`（或 `$matrix`）看实际角度是否累加 |
| 影响面 | 编辑器操作 + 导出结果错误 |
| 改动位置 | `BackgroundEditor.vue` 的 `rotate()` 与模板 L351-352 |

## 5. 放大、缩小按钮**都是放大**，缩小无效

| 项 | 内容 |
|---|---|
| 状态 | **已定位（源码级确认）** |
| 现象 | 点「放大」和「缩小」效果一样，都在放大 |
| 定位结果 | 读 `node_modules/cropperjs/dist/cropper.js` 的 `$zoom` 实现：<br>`if (scale < 0) { scale = 1 / (1 - scale) } else { scale += 1 }`<br>**参数是相对增量、不是倍率**。模板传 `zoom(1.1)` → 内部变成 `2.1`（放大 2.1 倍）；传 `zoom(0.9)` → 变成 `1.9`（**仍然是放大**）。所以两个按钮都在放大 |
| 修法（待实施） | 要么按增量语义传（放大 `0.1`、缩小 `-0.1`），要么绕过 `$zoom` 直接用 `$scale()` 做绝对缩放（语义更清楚） |
| 影响面 | 编辑器操作 |
| 改动位置 | `BackgroundEditor.vue` 的 `zoom()` 与模板 L355-356 |
| 备注 | 这条最容易修，改完可立刻验证 |

## 7. ⚠️ 预览与 OBS 里实际显示**不一致**（比"字小"严重）

| 项 | 内容 |
|---|---|
| 状态 | **暂不修改（用户决定）** |
| 现象（初报） | 右栏预览里字号/字重的变化看不出来 |
| 现象（追问后修正） | **预览的效果和真正在 OBS 里看到的不一样**——这不只是"看不清"，而是**预览不能代表真实结果** |
| 为什么这比"字小"严重 | 预览存在的全部意义就是"所见即所得"。若它和 OBS 不一致，用户照着预览调样式，在 OBS 里会得到另一个样子——**预览反而误导人** |
| 已定位的直接原因 | 为修正比例，iframe 按 960×540 虚拟画布渲染，再 `transform: scale(0.36)` 缩到约 346px 宽 |
| 为什么缩放会导致不一致（待验证的怀疑点） | 需要实测确认是下面哪一条，**不能猜**：<br>① 面板 CSS 里有基于视口/`vh` 的尺寸（缩放后参照系变了）；<br>② 面板用 `zoom` 变量做整体缩放，与我这层 `transform: scale` **叠加**，等于缩放了两次；<br>③ 面板按 960px 宽排版，而用户 OBS 里的源实际是别的宽度（例如 1920 或一个窄条），换行与 `wide` 布局比例自然不同；<br>④ 字体在非整数缩放下渲染差异被放大 |
| 结论 | **在确认"预览 == OBS"之前，第 7 条不修**。修法取决于上面哪一条成立 |
| 影响面 | 只影响设置页可读性/可信度，不影响 OBS 实际输出 |
| 改动位置 | `ObsPanel.vue` 预览区 |
| 备注 | 用户原话：「我发现预览和实际在 OBS 里不一样，还是先不改」 |
