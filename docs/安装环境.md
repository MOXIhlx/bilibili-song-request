# 安装环境说明

本文只讲**怎么把环境和依赖装好**，跑起来之后的用法见 [README](../README.md)；
播放列表/队列的设计与改动记录见 [播放列表重构设计](播放列表重构设计.md)。

先确定你要哪一种：

| 你的目标 | 需要装什么 | 跳到 |
|---|---|---|
| **A. 装完即用**（拿到 `*_x64-setup.exe` 安装包） | 只要 WebView2（Win11 自带）——**mpv 已随包内置** | [第 3 节](#3-只想用运行现成的-exe) |
| **B. 从源码构建**（并打出安装包） | 上面 + Node.js + Rust + MSVC 生成工具 | [第 4 节](#4-从源码构建装全套工具链) → [第 6 节](#6-打成安装包自带前端推荐) |
| **C. 只有裸 exe**（不打包） | 同上，且 exe 旁边必须有 `dist/` **和 `mpv.exe`** | [第 4.6 节](#46-得到可以直接双击运行的-exe) |

> ✅ **安装包已自带前端资源与 mpv**，装完就是能直接播的独立程序：
> 不需要单独装 mpv，也不需要带着 `dist/` 文件夹。
> mpv 由构建时的 `bundle.externalBin` 打进安装包，安装后落在程序同级的 `mpv.exe`。
>
> 只有不打包、直接跑裸 exe 的路线（C）才需要自己准备 `dist/` 和 `mpv.exe`。

## 1. 版本要求一览

| 依赖 | 最低版本 | 用途 | 是否必需 |
|---|---|---|---|
| Windows | 10 x64（1903+）/ 11 | 运行平台 | ✅ 必需 |
| WebView2 Runtime | 任意 | 渲染界面（Tauri 的窗口内核） | ✅ 必需 |
| mpv | 0.36 | 真正出声的播放引擎 | ⭐ 强烈建议（缺了程序能开，但没声音） |
| Node.js | 18（推荐 20 / 22 LTS） | 前端构建 | 仅构建需要 |
| Rust | stable ≥ 1.77（`Cargo.toml` 的 `rust-version`） | 后端编译 | 仅构建需要 |
| MSVC 生成工具 | VS 2022 Build Tools + VCTools | 提供 Rust 的链接器 `link.exe` | 仅构建需要 |

本项目在 **Node v24.9.0 / Rust stable(MSVC) / PowerShell 5.1** 上验证通过。
注意：机器上必须有 **PowerShell 5.1**（Windows 自带即可），`pwsh`（PowerShell 7）**不是必需的**。

## 2. 先自检：你现在缺什么

打开 PowerShell，逐条粘贴执行，看哪些报错：

```powershell
node -v          # 期望 v18+（前端构建）
npm -v
rustc -V         # 期望 rustc 1.77+
cargo -V
mpv --version    # 期望 mpv 0.36+（没装也不影响启动，只是没声音）
where.exe link   # 期望能找到 link.exe（MSVC 链接器）
```

检查 WebView2 是否已安装（Win10 需要确认，Win11 一般自带）：

```powershell
# 有输出（版本号）就说明已安装
Get-ItemProperty 'HKLM:\SOFTWARE\WOW6432Node\Microsoft\EdgeUpdate\Clients\{F3017226-FE2A-4295-8BDF-00C3A9A7E4C5}' -Name pv -ErrorAction SilentlyContinue | Select-Object -ExpandProperty pv
```

更简单：直接运行程序。**缺 WebView2 时窗口会是全白或直接不出现**，这是最典型的症状。

## 3. 只想用：运行安装包

**只需要 WebView2**（Win11 自带）——**mpv 已经打包在安装包里，不用你装**。

1. 双击 `bilibili-song-request_<版本>_x64-setup.exe`，按提示安装
   （默认只装当前用户，**不需要管理员权限**）
2. 从开始菜单启动「墨墨弹幕点歌机」

安装后的目录长这样，`mpv.exe` 就是内置的播放引擎：

```text
%LOCALAPPDATA%\bilibili-song-request\
├── bilibili-song-request.exe   约 12.6 MB
├── mpv.exe                     约 115 MB（内置，程序同目录优先使用）
├── uninstall.exe
└── _up_\dist\                  前端资源
```

> 💡 程序查找 mpv 时**优先用同目录的**，所以内置的这份一定生效；
> 你系统里另外装过 mpv 也不影响（不会串用）。

### 3.1 WebView2 运行时

Windows 11 自带，跳过。Windows 10 若缺失，任选一种：

```powershell
# 方式一：winget
winget install --id Microsoft.EdgeWebView2Runtime -e

# 方式二：微软官网下载「Evergreen Standalone Installer」
# https://developer.microsoft.com/microsoft-edge/webview2/
```

### 3.2 只有裸 exe 时才需要自己准备 mpv

如果你拿到的**不是安装包**，而是单独的 `bilibili-song-request.exe`，
那就需要自己放一份 mpv。两种方式程序都支持：

```powershell
winget install shinchiro.mpv
```

> ⚠️ **装完必须重启点歌机**。mpv 路径只在**程序启动时探测一次**，
> 在程序运行期间新装的 mpv 不会被发现——这是「明明装了却说没检测到」最常见的原因。

**方式 A：winget 安装（推荐）** → 装到 `C:\Program Files\MPV Player\`，程序自动找到。

**方式 B：下载 7z 压缩包解压** → 解压后是 `mpv\` 目录里含 `mpv.exe`。
把整个解压结果放到程序目录旁边即可：

```text
<便携版目录>\
├── bilibili-song-request.exe
├── mpv\                       ← 解压出来的发行包
│   ├── mpv.exe
│   └── d3dcompiler_43.dll
└── _up_\dist\
```

也可以直接把 `mpv.exe` 拿出来放在程序同级：

```text
<便携版目录>\
├── bilibili-song-request.exe
├── mpv.exe                    ← 只放这一个文件也行
└── _up_\dist\
```

> ⚠️ 单独把 `mpv.exe` 拿出来放时，**要连 `d3dcompiler_43.dll` 一起拿**，
> 否则部分机器上 mpv 会启动失败（缺 DLL）。

程序的完整查找顺序：

1. 环境变量 `BSR_MPV_PATH` 指定的路径（优先级最高）
2. 程序目录，以及**向上 4 级**的每一层，依次找：
   - `mpv.exe`
   - `binaries\mpv.exe`、`binaries\mpv-<target-triple>.exe`（Tauri sidecar 布局）
   - **`mpv\mpv.exe`**、`mpv\installer\mpv.exe`（7z 解压出来的发行包）
   - `bin\mpv.exe`
3. 系统安装位置：`C:\Program Files\MPV Player\`、`C:\Program Files (x86)\MPV Player\`、
   `C:\Program Files\mpv\`、`C:\mpv\`、`%LOCALAPPDATA%\Programs\mpv\`、
   `%LOCALAPPDATA%\mpv\`、winget 便携包目录
4. 系统 `PATH`

都找不到时程序**仍能启动**（只是没有声音），日志里会有一条自解释的错误，
列出所有尝试过的路径——照着它把 mpv 放对位置即可。也可以手动指定（当前会话有效）：

```powershell
$env:BSR_MPV_PATH = "C:\Program Files\MPV Player\mpv.exe"
.\bilibili-song-request.exe
```

### 3.3 音频要能被 OBS 采集

程序**故意**不让面板出声：音频由 mpv 直接输出到系统音频设备。
所以要在 OBS 里加「**音频输入采集 → 桌面音频**」，否则观众听不到声音。

## 4. 从源码构建：装全套工具链

### 4.1 Node.js

```powershell
winget install --id OpenJS.NodeJS.LTS -e
# 重新打开终端
node -v ; npm -v
```

### 4.2 Rust

```powershell
winget install --id Rustlang.Rustup -e
# 重新打开终端
rustc -V ; cargo -V
```

Rust 默认使用 **MSVC 工具链**（`stable-x86_64-pc-windows-msvc`），
确认一下：

```powershell
rustup show          # 应显示 default toolchain: stable-...-msvc
```

### 4.3 MSVC 生成工具（最容易漏的一步）

Rust 的 MSVC 工具链需要 `link.exe`，它来自 Visual Studio 的 C++ 工具集。
**只装 Rust 是不够的**——没有它编译会报 `link.exe not found`。

```powershell
winget install --id Microsoft.VisualStudio.2022.BuildTools -e --override "--wait --quiet --add Microsoft.VisualStudio.Workload.VCTools --includeRecommended"
```

装完**必须重新打开终端**，然后验证：

```powershell
where.exe link       # 应输出 link.exe 路径
```

> 只装 `Microsoft.VisualStudio.2022.BuildTools` 而不加 `--add Microsoft.VisualStudio.Workload.VCTools`
> 是不行的：那只会装 VS 安装器外壳，没有编译器。

### 4.4 拉依赖并构建

```powershell
cd bilibili-song-request

npm install                 # 前端依赖（约 80 MB）
npm run build               # 产出 dist/（index.html / panel.html / dashboard.html）
                            # 顺带校验三处版本号一致

cd src-tauri
cargo check                 # 后端编译检查（首次约 1-3 分钟）
cargo test                  # 跑单元/集成测试
```

首次 `cargo build` 需要下载并编译全部依赖，**大约 3-5 分钟**（视机器而定），
之后增量编译通常几秒。

### 4.5 运行方式

| 目标 | 命令 | 说明 |
|---|---|---|
| 桌面应用（开发 + 热更新） | `npm run tauri:dev` | 同时拉起 vite(1420) 与 Tauri 窗口 |
| 只编 exe（最快，推荐） | `cargo build --release`（在 `src-tauri/`） | 产物 `src-tauri\target\release\bilibili-song-request.exe` |
| 打安装包 | `npm run tauri:build` | ⚠️ 当前 `bundle.active = false`，不会产出安装包 |

### 4.6 得到"可以直接双击运行"的 exe

`cargo build --release` 的产物在 `src-tauri\target\release\` 里。可以直接运行它，
但有两个坑要知道：

**坑 1：必须先 `npm run build`。** exe 需要 `dist/` 里的前端产物——
程序启动时按 `BSR_DIST_DIR` → exe 同级/上级的 `dist/` → 仓库根 `dist/` 去找。
只编 Rust 不编前端，窗口会打开但界面是空的。

**坑 2：替换 exe 时旧进程必须已退出。** 应用运行时 exe 被占用，
`Copy-Item` 会**静默失败**（如果加了 `-ErrorAction SilentlyContinue` 就更难发现），
于是你运行/验证的其实还是**上一次的旧版本**。这个坑在本项目里真实发生过，
排查了很久。稳妥做法（仓库自带脚本，会逐步自校验）：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/rebuild-and-restart.ps1
```

它做的事：结束进程并等待文件锁释放 → 删除旧 exe → 编译并检查退出码 →
复制后比对 **SHA256** → 启动并轮询 `/health` → 确认运行中的进程路径就是刚构建的 exe。

想手动做的话，至少要确认版本号真的变了：

```powershell
# 构建并替换
Stop-Process -Name bilibili-song-request -Force -ErrorAction SilentlyContinue
Start-Sleep -Seconds 8
cargo build --release
Copy-Item src-tauri\target\release\bilibili-song-request.exe . -Force
.\bilibili-song-request.exe

# 另开终端确认运行的是新版本
curl.exe -s http://127.0.0.1:17777/health
```

`/health` 返回的 `version` 与 `package.json` 一致，才说明跑的是新构建。

只跑后端 + 网页面板（不开桌面窗口）：

```powershell
cd src-tauri
cargo run
# 然后浏览器打开 http://127.0.0.1:17777/panel 或 /dashboard
# 注意：前端要先 npm run build，或用 BSR_DIST_DIR 指向 dist 目录
```

启动成功的标志（日志与终端都会打印）：

```text
面板地址：http://127.0.0.1:17777/panel
控制台地址：http://127.0.0.1:17777/dashboard
```

用 `/health` 快速确认服务活着、以及当前版本号：

```powershell
curl.exe -s http://127.0.0.1:17777/health
# {"status":"ok","version":"1.0.2","uptime_secs":1}
```

## 5. 装完之后：验证清单

按顺序做，每步都有明确预期，出错就能定位到是哪一层的问题。

| # | 操作 | 预期 |
|---|---|---|
| 1 | `node -v` / `rustc -V` | 有版本号输出 |
| 2 | `where.exe link` | 输出 `link.exe` 路径 |
| 3 | `cargo test`（在 `src-tauri/`） | 全部通过（本项目为 315 个用例） |
| 4 | `npm run build` | `版本一致：x.y.z` + `✓ built in ...` |
| 5 | 启动程序 | 出现窗口，日志打印两个地址 |
| 6 | `curl.exe -s http://127.0.0.1:17777/health` | 返回 `"status":"ok"` |
| 7 | 控制台 →「链路自测」注入 `点歌 晴天 周杰伦` | 队列里出现这条；面板同步显示 |

第 7 步**不需要** B 站身份码，也不一定需要音乐平台登录——
但**没登录音乐平台时可能取不到播放地址**（版权曲），日志里会看到
`未登录，跳过 eapi` / `该歌曲无法获取播放地址`，这是正常的，登录后即可播放。

## 6. 打成安装包（自带前端，推荐）

安装包**自带前端资源**，装完是一个独立程序，不需要再带着 `dist/` 文件夹。
构建缓存被清理过，首次打包需要全量编译（约 3-5 分钟）。

```powershell
npm run tauri:build
```

产物在 `src-tauri\target\release\bundle\nsis\`，形如
`bilibili-song-request_1.0.5_x64-setup.exe`（**约 36.6 MB**，含内置 mpv），
默认只装当前用户、**不需要管理员权限**。

### 打包前必须先准备 mpv sidecar

安装包里的 mpv 来自 `src-tauri/binaries/`，**这个文件不入库**（115 MB），
所以每次在新机器上打包前要先执行一次：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/fetch-mpv.ps1
```

它会从 shinchiro 的 release 下载 `mpv-x86_64-*.7z`（约 32 MB），
解压后只把 `mpv.exe` 复制成 sidecar 要求的名字
`src-tauri/binaries/mpv-x86_64-pc-windows-msvc.exe`（约 115 MB）。

> 实测：单独的 `mpv.exe` **可以独立运行**（静态链接，不需要同包的
> `d3dcompiler_43.dll`），所以只复制主程序是够的。
>
> 想换更新版本时加 `-Force` 重新下载：
> `... -File scripts/fetch-mpv.ps1 -Force`

配置侧只需一行（已配好）：

```json
"bundle": { "externalBin": ["binaries/mpv"] }
```

Tauri 会把 `<name>-<target-triple>.exe` 打进安装包，**安装后重命名为 `mpv.exe`**
放在程序同级；程序查找 mpv 时同目录优先，因此内置这份一定生效。

### ⚠️ 国内网络：下载 mpv 与 NSIS 工具链都需要代理

首次打包要从 GitHub 下载 NSIS 工具链、以及上面那份 mpv，
**直连会超时**，报：

```
Error failed to bundle project: `timeout: global`
```

给构建进程带上代理环境变量即可（端口换成你自己的）：

```powershell
$env:HTTPS_PROXY = 'http://127.0.0.1:26561'
$env:HTTP_PROXY  = 'http://127.0.0.1:26561'
npm run tauri:build
```

两者都只下载一次：NSIS 缓存在 `%LOCALAPPDATA%\tauri\NSIS\`，
mpv 落在 `src-tauri/binaries/`（已在 `.gitignore` 中忽略）。

### 安装后的目录结构

```
%LOCALAPPDATA%\bilibili-song-request\
├── bilibili-song-request.exe
├── mpv.exe                  ← 内置播放引擎（externalBin 带入）
├── uninstall.exe
└── _up_\dist\              ← 前端资源（由 resources 配置带入）
    ├── index.html  panel.html  dashboard.html
    └── assets\
```

> 📌 `_up_` 这个名字不是笔误：Tauri 打包 `resources` 时会把源路径里的 `..`
> 重写成 `_up_`（见 tauri-utils 的 `resource_relpath`），而 Windows 上
> `resource_dir()` 就是 exe 所在目录。所以 `resources: ["../dist"]`
> 最终落在 `<安装目录>\_up_\dist\`，`webdist.rs` 会专门探这一层。

### mpv 已经内置，不需要目标机器再装

安装包通过 `bundle.externalBin` 把 mpv 一起带上了（见上一节），
所以**目标机器不需要 `winget install shinchiro.mpv`**。

如果用户**另外**装了系统级 mpv 也不会串用——程序查找顺序里
「程序同目录的 `mpv.exe`」排在「系统安装位置」之前。

### 不想内置 mpv（想缩小安装包）

把 `tauri.conf.json` 里的 `"externalBin": ["binaries/mpv"]` 去掉即可，
安装包会从约 36.6 MB 降到约 3.6 MB，代价是用户要自己装 mpv：

```powershell
winget install shinchiro.mpv
```

两种策略的取舍：

| 策略 | 安装包体积 | 用户体验 |
|---|---|---|
| **内置 mpv**（当前） | 约 36.6 MB | 装完即用，零操作 |
| 不内置 | 约 3.6 MB | 用户需自己装 mpv（或把 `mpv.exe` 放到程序旁） |

## 7. 常见错误与解决

### `link.exe not found` / `error: linker 'link.exe' not found`

缺 MSVC 生成工具。按 [4.3](#43-msvc-生成工具最容易漏的一步) 安装后**重开终端**。
装了 VS Code 或「Visual Studio 生成工具」但没勾 C++ 工作负载也会这样。

### `failed to find tool. Is 'cl.exe' installed?`

同上，MSVC 工具集缺失。

### 窗口全白 / 程序启动了但看不到界面

缺 WebView2 运行时。按 [3.1](#31-webview2-运行时) 安装。
（Win11 极少见；Win10 精简版系统常见。）

### `npm run build` 报版本不一致并失败

项目要求三处版本号一致：`package.json`、`src-tauri/tauri.conf.json`、`src-tauri/Cargo.toml`。

```powershell
npm run check:versions    # 看哪一处不一致
npm run fix:versions      # 以 package.json 为准自动同步另两处
```

### 端口 17777 被占用

程序会**自动改用系统分配的空闲端口**，并在日志里打印实际端口：

```text
端口绑定失败，改用系统分配端口重试
内嵌 HTTP/WebSocket 服务器已就绪 addr=127.0.0.1:17777 actual_port=xxxxx
```

之后请用日志里的 `actual_port` 访问面板/OBS 源。查占用进程：

```powershell
Get-NetTCPConnection -LocalPort 17777 -ErrorAction SilentlyContinue |
  Select-Object OwningProcess, State
```

### `cargo test` 偶发失败（exit code 101）

并行链接时的偶发竞争。**重跑一次**通常就全绿。
本项目曾观察到「输出显示 315 passed，但退出码非 0」的情况。

### 没有声音

1. 确认装了 mpv：`mpv --version`
2. 让程序先把音量调起来（播放器卡片有音量滑块）
3. OBS 侧要在**混音器**里加「桌面音频」，面板本身不出声是设计如此
4. 看日志有没有 `mpv 已就绪，播放功能可用`；如果是 `未找到 mpv`，用 `BSR_MPV_PATH` 指定

### 想用便携模式（配置不写进 %APPDATA%）

```powershell
$env:BSR_CONFIG_DIR = "D:\danmaku-data"
.\bilibili-song-request.exe
```

配置 / 日志 / 队列 / 密钥都会放进该目录，整个文件夹拷走就能换机器用。

## 8. 环境变量速查

| 变量 | 作用 |
|---|---|
| `BSR_MPV_PATH` | 直接指定 `mpv.exe` 路径（优先级最高） |
| `BSR_CONFIG_DIR` | 覆盖配置目录（便携模式） |
| `BSR_DIST_DIR` | 指定前端构建产物目录（默认 `dist`） |
| `BSR_LOG` | 日志级别，如 `bilibili_song_request_lib::player=debug,info` |
| `BSR_NETEASE_API_BASE` | 覆盖网易云接口域名（镜像 / 本地桩服务） |
| `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS` | 打开调试端口，用于界面自检，如 `--remote-debugging-port=9333` |

例：打开调试端口后用仓库脚本查界面状态

```powershell
$env:WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS = "--remote-debugging-port=9333"
.\bilibili-song-request.exe
# 另开一个终端
node scripts/tauri-eval.mjs "document.title" 9333
```

## 10. 换了一台电脑后不能播放？先跑诊断

在**新电脑**上装好便携版后如果播放失败，不要猜——用诊断脚本定位。

### 怎么跑（两种方式，任选）

**方式一：双击 `diagnose.bat`（推荐）**

把 `docs\diagnose.bat` 和 `docs\诊断.ps1` 一起复制到便携版目录，
并把 `诊断.ps1` 改名为 **`diagnose.ps1`**（ASCII 名字更稳），然后双击 `diagnose.bat`：

```text
<便携版目录>\
├── bilibili-song-request.exe
├── diagnose.bat          ← 双击这个
├── diagnose.ps1
└── _up_\dist\
```

窗口会在结束时停在 `press any key`，**不会一闪而过**。

**方式二：右键 `诊断.ps1` → 使用 PowerShell 运行**

脚本自己也会在结束时暂停等你按回车。
（如果你看到窗口一闪而过，说明用的是旧版脚本，用方式一最保险。）

它只做**只读检查**（不改配置、不删文件、不发起点歌），会逐项报告：

1. 便携版布局是否完整（`_up_\dist\` 及 assets 是否存在）
2. WebView2 运行时是否安装
3. mpv 是否找到、版本是多少
4. 内嵌服务器：`/health`、`/api/state`、`/api/player/status`、`/api/music/status`、`/api/bilibili/status`
5. `/panel`、`/dashboard` 是否正常返回（而不是「前端资源尚未构建」提示页）
6. 端口与代理设置
7. 应用日志里最近的 WARN / ERROR

把输出整段复制回来，就能直接定位问题。

### 换机器后最常见的四个原因

| 症状 | 原因 | 解决 |
|---|---|---|
| 界面提示**无法播放**，且 `/api/player/status` 里 `available: false` | mpv 没被找到。**安装包已内置 mpv**，出现这行通常意味着你跑的是裸 exe、或内置的 `mpv.exe` 被删了 | 用安装包装一次；或 `winget install shinchiro.mpv` / 设 `BSR_MPV_PATH` |
| 报**该歌曲无法获取播放地址（版权限制）**，日志有 `未登录，跳过 eapi` | 新机器没登录音乐平台 | 在「音乐平台」卡片重新登录 |
| 日志出现 `B 站配置不完整：缺少 app_id` | 新机器没填过 B 站身份码 | 在「B 站弹幕连接」卡片重新填写 |
| 窗口全白 / 打不开 | 新机器缺 WebView2 运行时 | 装 [WebView2 Runtime](https://developer.microsoft.com/microsoft-edge/webview2/) |

> ⚠️ **便携版并不是"凭据也能带着走"**。
> `config.json` / `queue.json` / 日志在便携模式（`BSR_CONFIG_DIR`）下确实同目录，
> 但 **音乐平台 Cookie 与 B 站 secret 存在 Windows 凭据库里**
> （诊断输出里会显示 `stored_in=keyring`），换机器必须重新登录 / 重新填身份码。
>
> 换机器时如果要连配置一起带走，可以直接复制整个
> `%APPDATA%\bilibili-song-request\`（含 `config.json`、`queue.json`、`backgrounds\`），
> 但**凭据仍需在新机器上重新登录**。
