# 开发调试指南（VSCode，不打包）

> 目标：改代码后**立刻看到效果**，不用每次 `tauri build` 打安装包。
>
> 打包流程见 [`开发日志.md` §10](../开发日志.md)。

---

## 0. 先理解三层结构

这个项目同时跑着**三个东西**，搞清楚它们才能知道"我改的东西要怎么看"：

| 层 | 是什么 | 端口 | 谁在看 |
|---|---|---|---|
| **Vite 开发服务器** | 前端源码 + 热更新（HMR） | `1420` | 你自己（浏览器 / Tauri 窗口） |
| **Rust 后端** | 内嵌 axum：API、WebSocket、给 OBS 的页面 | `17777` | OBS 浏览器源、网页面板 |
| **Tauri 桌面窗口** | WebView2 外壳，加载前端 | — | 你自己 |

### ⚠️ 一个最容易踩的坑

**Rust 后端提供的前端，不是 Vite 那份。**

后端按固定顺序找 `dist/`（见 `src-tauri/src/webdist.rs`），优先级最高的是环境变量
`BSR_DIST_DIR`。所以：

- 你改前端 → **Tauri 窗口**（走 Vite）会热更新，**立刻能看到**；
- 但在 **OBS / 浏览器**里打开的 `http://127.0.0.1:17777/panel` 走的是后端，
  **除非重新 `npm run build` 或设置 `BSR_DIST_DIR`，否则它还是旧的**。

> 这个坑在开发中真实踩过：改了面板样式，Vite 里好好的，OBS 里死活不变——
> 因为 OBS 加载的是后端那份旧的 `dist`。

**两种解法，按需选：**

```powershell
# 解法 A：改完前端构建一次（最简单，推荐日常用）
npm run build
#   产物在 dist/。后端会自动找到它（exe 同级或仓库根）。

# 解法 B：让后端每改一次前端就自动重建（适合频繁调 OBS 里的显示）
npm run build -- --watch
#   跑着别关，它会在你保存 .vue 时自动重新构建 dist/。
#   然后把浏览器源刷新一下（OBS 里右键 → 刷新页面）就能看到新版本。
```

> `BSR_DIST_DIR` 是用来**换一个 dist 目录**（例如指向另一份构建产物），
> 它**不能**直接指向 Vite 的开发服务器（1420）——后端要的是一个装着
> `panel.html` / `dashboard.html` 的**目录**，不是一个 URL。
> 所以"改前端立刻在 OBS 里生效"的正解是**解法 B**（watch 构建 + 刷新）。
>
> 日常看界面用 `tauri:dev` 就够了；只有调 OBS 实际显示时才需要管这一层。

## 1. 最短路径（日常开发）

```powershell
cd D:\deepseek\bilibili-song-request

# 装依赖（第一次，或 package.json 变过之后）
npm install

# 一条命令拉起全部：vite + Rust 后端 + Tauri 窗口
npm run tauri:dev
```

会发生什么：

1. Vite 起在 `http://localhost:1420`（`strictPort`，被占用会直接报错而不是换端口）
2. Rust 以 **debug** 编译并运行（首次约 1~3 分钟，之后增量很快）
3. Tauri 窗口打开，指向 Vite
4. **改 `.vue` / `.ts` → 窗口里立刻更新**（不用重启）
5. **改 `.rs` → 自动重新编译并重启窗口**

> 在 VSCode 里等价于：`Ctrl+Shift+P` → `Tasks: Run Task` →
> **「开发：tauri dev（热更新，日常用这个）」**，
> 或直接 `Ctrl+Shift+B`（它是默认构建任务）。

### 关掉它

在跑任务的终端里 `Ctrl+C`。如果窗口没关干净：

```powershell
Get-Process -Name 'bilibili-song-request','mpv' -ErrorAction SilentlyContinue | Stop-Process -Force
Get-Process -Name 'msedgewebview2' -ErrorAction SilentlyContinue | Stop-Process -Force
```

## 2. 在浏览器里调前端（DevTools 更好用）

Tauri 窗口的 DevTools 也能开，但浏览器里更顺手（React/Vue DevTools、性能面板等）。

**需要两个终端：**

```powershell
# 终端 1：后端（给 vite 代理用）
npm run tauri:dev      # 想同时看窗口
# 或只要后端、不要窗口：
cd src-tauri; cargo run

# 终端 2：前端
npm run dev
```

然后打开：

| 地址 | 是什么 |
|---|---|
| `http://localhost:1420/dashboard.html` | 主播控制台（浏览器版） |
| `http://localhost:1420/panel.html` | OBS 面板页 |
| `http://localhost:1420/` | Tauri 窗口用的 SPA（含路由，浏览器里也能开） |

`vite.config.ts` 里配了代理，所以前端代码里始终写相对路径 `/api`、`/ws`：

```ts
'/api' → http://127.0.0.1:17777
'/ws'  → ws://127.0.0.1:17777   （开了 ws: true）
```

**VSCode 里调试**：`F5` → 选
**「前端：调试网页面板（需先 npm run dev）」**，会自动开浏览器并挂上调试器，
源码断点直接可用（Vite 的 sourcemap）。

## 3. 调试只能在桌面窗口里复现的问题

有些东西浏览器里没有：Tauri 命令、原生对话框、窗口尺寸相关行为。
这时用 WebView2 的远程调试端口：

```powershell
# 启动前设置（同一个终端里）
$env:WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS = "--remote-debugging-port=9333"

# 然后正常启动
npm run tauri:dev
# 或者跑一个 exe
.\dist-portable\bilibili-song-request.exe
```

打开 `http://127.0.0.1:9333` 就是一个完整的 DevTools。也可以：

```powershell
# 列出可调试目标
node scripts/tauri-eval.mjs --list 9333

# 直接在窗口里求值（调 Tauri 命令也能这么干）
node scripts/tauri-eval.mjs "document.title" 9333
node scripts/tauri-eval.mjs "window.__TAURI_INTERNALS__.invoke('plugin:dialog|open')" 9333
```

VSCode 里用 **「前端：附加到 Tauri 窗口」** 配置（`type: chrome` + `attach`）。

## 4. 调试 Rust 后端

**推荐装 [CodeLLDB](https://marketplace.visualstudio.com/items?itemName=vadimcn.vscode-lldb)**
（`.vscode/extensions.json` 里已列为推荐扩展）。

`F5` → **「后端：调试 Rust（cargo run）」**：会在
`src/main.rs` 等处断点生效，变量、调用栈都能看。

### 日志

Rust 侧用 `tracing`，日志级别由 `BSR_LOG` 控制：

```powershell
# 只看播放器相关的 debug 日志
$env:BSR_LOG = "bilibili_song_request_lib::player=debug,info"
npm run tauri:dev
```

`launch.json` 里的 Rust 配置已经把 `RUST_LOG` 设成 `debug`（并把
hyper/reqwest/tungstenite 这些网络库压到 warn，否则刷屏）。

## 5. 测试与检查

VSCode：`Ctrl+Shift+P` → `Tasks: Run Task`：

| 任务 | 等价命令 | 作用 |
|---|---|---|
| 检查：全套 | — | 依次跑下面三项 |
| 检查：版本号一致 | `npm run check:versions` | `package.json` / `tauri.conf.json` / `Cargo.toml` 三处版本必须一致 |
| 检查：前端类型 + 构建 | `npm run build` | `vue-tsc --noEmit` + `vite build` |
| 测试：Rust | `cargo test`（在 `src-tauri/`） | 当前 **333** 个用例 |
| 测试：前端 | `npm test` | `node --test tests/*.test.ts` |

**提交前跑「检查：全套」最省心。**

### 离线端到端验收（不依赖真实网易云）

真实直链是短时效 CDN 且受风控影响，无法稳定复现。项目自带桩服务：

```powershell
# 终端 1：桩服务（返回网易云真实响应结构，音频指向 C:\Windows\Media 的 wav）
node scripts/mock-music-server.mjs 18999

# 终端 2：把接口指向桩服务并启动
$env:BSR_NETEASE_API_BASE = "http://127.0.0.1:18999"
npm run tauri:dev

# 终端 3：加歌并播放（走真实解析链路）
curl.exe -X POST http://127.0.0.1:17777/api/queue/add -H "content-type: application/json" -d '{\"title\":\"本地测试曲一\",\"requested_by\":\"验收\"}'
curl.exe -X POST http://127.0.0.1:17777/api/player/play
```

### 没有 B 站身份码时怎么调面板

不用连直播也能看到面板效果——直接 `POST /api/queue/add` 加歌，
或在设置页调样式（预览是本地渲染的，改一下立刻变）。

## 6. 环境变量速查

| 变量 | 作用 | 开发时常用度 |
|---|---|---|
| `BSR_CONFIG_DIR` | 覆盖配置目录（配置/日志/队列/密钥都放这里） | ★★★ **强烈建议**：把开发数据与你的真实配置隔离 |
| `BSR_DIST_DIR` | 指定后端提供的前端目录 | ★★☆ 改前端又要看 OBS 效果时用 |
| `BSR_MPV_PATH` | 指定 `mpv.exe` 路径 | ★★☆ 系统里 mpv 不在默认位置时 |
| `BSR_NETEASE_API_BASE` | 覆盖网易云接口域名（镜像 / 本地桩） | ★★☆ 离线验收 |
| `BSR_LOG` | 日志级别 | ★☆☆ 排查后端问题时 |
| `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS` | 给 WebView2 加启动参数（开 9333 调试端口） | ★★☆ |

### 用临时配置目录，别动你的真实数据

程序默认读写 `%APPDATA%\bilibili-song-request`。**开发时建议隔离**：

```powershell
$env:BSR_CONFIG_DIR = "D:\deepseek\bilibili-song-request\.vscode\.dev-config"
npm run tauri:dev
```

`launch.json` 的 Rust 配置里预留了这一行（默认注释掉）。

> ⚠️ 开发中真实踩过：调试时误删了用户图库里的背景图，且**不可恢复**
> （早期删除是 `remove_file`，不进回收站）。现在删除已改为移入
> `backgrounds/.trash/`，但**隔离配置目录仍是最稳的习惯**。

## 7. 端口速查

| 端口 | 谁 | 冲突时怎么办 |
|---|---|---|
| `1420` | Vite | `strictPort: true`，被占用**直接报错**。改 `vite.config.ts` 的 `server.port`，并同步 `tauri.conf.json` 的 `devUrl` |
| `17777` | Rust 后端 | 改 `config.json` 的 `server.port` 后重启 |
| `9333` | WebView2 远程调试 | 换个端口号即可 |
| `18999` | 桩音乐服务 | 命令里换个数 |

**只有一份代码能占 17777**：便携版、`tauri:dev` 的后端、单独 `cargo run`
三者同时只能跑一个。切换前先关掉旧的：

```powershell
Get-Process -Name 'bilibili-song-request' -ErrorAction SilentlyContinue | Stop-Process -Force
```

## 8. 常见问题

**Q：改了前端，Tauri 窗口更新了，但 OBS 里没变。**
见本文开头的坑。`npm run build` 或设置 `BSR_DIST_DIR`。

**Q：`npm run tauri:dev` 报端口 1420 被占用。**
上一次的 vite 没退干净。找出来杀掉：

```powershell
Get-NetTCPConnection -LocalPort 1420 -State Listen | ForEach-Object { Stop-Process -Id $_.OwningProcess -Force }
```

**Q：窗口里显示「前端资源尚未构建」。**
后端起在了 17777，但它没找到 `dist/`。跑一次 `npm run build`，
或设置 `BSR_DIST_DIR`。

**Q：`cargo build` 成功了，但界面还是旧的。**
**这是本项目最容易浪费时间的坑**：前端是 `npm run tauri:build`
**嵌进 exe** 的，`cargo build --release` **不会**重新嵌入。
另外 WebView2 还会按 URL 缓存旧的 `assets/main-<hash>.js`。

→ 用 `scripts/build-release.ps1`，它会用 `tauri:build`、清 WebView2 缓存，
并**断言 exe 里确实含当前前端**：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/build-release.ps1
# 成功时会打印：OK: exe embeds main-XXXXXXXX
```

**Q：改 `src/types.ts` 后 Rust 侧对不上。**
两边字段必须逐字段一致（`src/types.ts` ↔ `src-tauri/src/models.rs`）。
`npm run build` 的 `vue-tsc` 只查前端，Rust 侧的字段不匹配要靠 `cargo test` 发现。

**Q：dev 模式首次编译特别慢。**
正常。首次要编译全部依赖。之后只编译改动的 crate。想让 dev 构建更快可以
在 `src-tauri/Cargo.toml` 里给 dev profile 加 `opt-level = 1` 给依赖
（代价是运行时略快、编译略慢，按需权衡）。
